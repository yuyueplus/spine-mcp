# Native editor bridge

This local interoperability adapter enables saved-project reload in a native Spine window. It is an unofficial startup Java agent for one verified installed build of Spine 4.3.23 (see `builds.json`). No Esoteric Software application files, third-party application bytecode, licensing logic or authentication logic are modified or distributed.

Use `spine_open_project` with `nativeBridge: true` and `reuseInstance: false`. Keep the returned `instanceId`. Query `spine_editor_state` to obtain the actual full project path, native unsaved predicate, identity, undo token and model proof. Pass those expected fields to `spine_reload_editor_project` with the NEW saved output from an MCP edit. The unified `spine_refresh_editor_view` also accepts `mode: editable_in_place`, `instanceId` and `expectedNativeState`.

The bridge operates on the native main thread and uses no mouse/keyboard injection or window activation command. Startup may activate a new window. It does not attach to an ordinary running editor. Other builds fail closed; ordinary opening and file-processing tools remain available. Updating the agent requires a new bridge-enabled window; existing windows are retained.

Reload refuses unsaved changes, stale state, interactive viewport edits, native dialogs, input drift, unsupported builds, parser warnings and invalid files. It first parses the candidate while retaining the old model, writes a **NEW sibling `.MCP-recovery-<requestId>.spine`** using the native writer and re-reads its model proof. Keeping the recovery file beside the current project preserves relative image paths. The original and candidate files are never overwritten. Retain the recovery snapshot while it is useful; the tool does not remove it automatically.

Successful reload replaces the editable model and **resets native undo history**. It restores setup/animate mode, the current frame, active animations, applied/edit skins, playback controls, and viewport cameras where names survive. Removed names are reported. Camera restoration follows a measured repaint barrier and at least 750 ms for the pinned build's pane transitions. This is an edit-time refresh, not a frame streaming player. UI input during refresh skips camera restoration; unsaved edits during repaint are retained and reported instead of being rolled back.

Receipts include actual native bone/slot/skin names and animation duration/key-count proof. The proof hash also covers captured native keyframe float/int values; it is not a serialization of all possible editor metadata. A native repaint counter confirms frame processing, not aesthetic quality. If native application fails, the old model/view are restored and checked. Read the rollback receipt; do not infer recovery from process survival.

Local file RPC uses a random per-instance secret, HMAC-authenticated requests/responses, typed commands, hash checks and a persistent request journal. Credentials are not included in tool results. A pending reply is not a completion: query `spine_editor_request_status` with the same `instanceId`/`requestId` after reconnect. Reusing an ID with different input is rejected. The editor and its agent survive MCP disconnects. The optional passive AWT listener records only an input revision counter within this JVM; no keys, text, coordinates or input from other applications are recorded.

Each launched instance uses its own immutable `agent.jar` copy, so replacing the installation does not alter a live agent. Startup directory arguments are UTF-8/base64url encoded to survive Windows launcher code pages. `nativeAwtWindowFocused` is JVM-local AWT state and must not be used as proof of the OS foreground window; foreground acceptance is separately observed through passive UI Automation.

The packaged JAR and its Java sources are pinned in `bundle.json`. Running the bridge needs no JDK. Developers can rebuild with `npm run build:editor-bridge -- --jdk <JDK-directory>` (or invoke `node dist/scripts/build-native-editor-bridge.js --jdk ...`); Java 8 bytecode runs in the editor's bundled JVM. Rebuild only after reviewing adapter changes and repeating native acceptance. Experimental reflection/JAR-loading probes under `work/` are excluded from releases.

## Guarded timeline controls (3.3.0)

`spine_control_editor_timeline` selects animation/skeleton, sets a paused frame, and plays or pauses in a NEW current-bundle bridge window. Supply the fresh path/identity/model/undo expectations from `spine_editor_state`. The native-thread response verifies the applied view after a repaint barrier and verifies that both the model hash and undo token remain unchanged. These view operations preserve undo; full project reload still resets it. Pending receipts require polling, and unsupported builds, dirty/stale/busy states refuse. No incremental structural edit API or hot attachment to an ordinary window is provided.
